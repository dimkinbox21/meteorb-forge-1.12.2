Scaffold on 1.12.2: bridges gaps and pillars up

Scaffold is ported and confirmed in game - the log shows the pillar climbing
y=80 to y=85 while jump was held, one block placed per level against the
neighbour above, exactly as on 1.8.

It needed only the placement call reworked. In 1.8 that was
PlayerControllerMP.func_178890_a(EntityPlayerSP, WorldClient, ItemStack,
BlockPos, EnumFacing, Vec3), whose name is already known and fixed; in 1.12.2
it is processRightClickBlock(EntityPlayerSP, WorldClient, BlockPos,
EnumFacing, Vec3d, EnumHand) - the hand parameter arrived with 1.9 and moved
everything after the world along by one. So the method is now found by SHAPE
rather than by name: whichever declared method takes a position, a face and a
hand and reports a verdict. The first attempt matched on "ItemStack at index
2", which is 1.8's order, and therefore never found the 1.12.2 method at all -
NoSuchMethodException in the log. The argument list is rebuilt from whichever
shape was found, and the result is read the same way: 1.8 answered boolean,
1.12.2 an EnumActionResult, so a TRUE boolean or anything but FAIL counts.

Two more 1.12.2 changes absorbed: MathHelper.floor_double is now
MathHelper.floor, and getCollisionBoundingBox takes the block state first.

Diagnostics that were in the port (aim/placeSlot/nbr/result on System.err) are
removed now that the shape was confirmed; package.cmd had %JAVAC% unset, which
silently skipped compiling the tools each run, and that is set now.
